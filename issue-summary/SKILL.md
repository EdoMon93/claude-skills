# Issue summary

Identify the working repo and its issue tracker from repo guidance and available context. Don't assume the tracker matches the code host. Ask the user if the service or repo scope is unclear.

Get the repo's open issues from its tracker, including enough context to explain the problem or intended change. Check ongoing work wherever the repo tracks it and other active threads.

Give a short overview in chat. For each issue, include its link and one sentence explaining what it would fix or enable. Connect ongoing work to its issue where possible, state its current progress. Group related items when useful without losing individual issue references.

Keep it concise. State any unavailable sources or partial coverage so missing data isn't mistaken for no open issues or ongoing work.
